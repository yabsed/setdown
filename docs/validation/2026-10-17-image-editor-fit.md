# 사진 편집 이미지 흔들림 수정

2026년 10월 17일, 사진 편집의 Fit 화면에서 입력 없이 이미지가 커졌다 작아지는 문제를 수정했다. [사용자 녹화](<../error-videos/스크린캐스트 2026-10-17 16-47-06.mp4>)의 스크롤바 반복 생성과 이미지 크기 변화를 확인하고, 실제 Electron의 연속 프레임 측정으로 재현했다.

## 원인과 수정

[ImageEditorSurface](../../apps/desktop/src/renderer/image/ImageEditorSurface.svelte)의 ResizeObserver가 `clientWidth`와 `clientHeight`를 맞춤 배율에 사용했다. 이 값은 정수로 반올림되고 현재 스크롤바의 크기를 제외한다. 일부 창 크기와 앱 배율 조합에서 stage가 실제 영역을 조금 넘으면 스크롤바가 생기고, 다음 관측에서는 내부 영역이 줄어 이미지가 작아졌다. 스크롤바가 사라지면 다시 커지는 순환이 이어졌다.

수정한 Fit 계산은 스크롤바와 독립적인 소수점 외부 CSS 영역을 사용한다. Fit에서는 스크롤 넘침을 막고, stage의 최소 크기는 CSS의 100%로 처리한다. 100% 등 숫자 배율에서는 원래 크기의 이미지와 스크롤·이동을 유지한다. 자르기 좌표, 파일 출력 크기와 편집 기록은 이 화면 배치에 영향을 받지 않는다.

첫 구현의 검사는 파일 저장과 편집 기능, 순간 화면 상태를 확인했으나 편집 화면의 소수 배율에서 지속되는 레이아웃 변화를 검사하지 않았다. 새 회귀 검사는 90%·120%·130% 앱 배율에서 90프레임을 수집하고, 초기 전환 이후 이미지 위치·크기 변화가 1 CSS px 미만인지 검사한다. 100% 확대에서 스크롤한 뒤 Fit으로 돌아오는 경로와 편집 상태·자르기 좌표도 함께 확인한다. 기존 검사나 허용치를 낮추지 않았다.

## 재현과 수정 결과

Xvfb, 독립 런타임 디렉터리와 D-Bus 세션의 실제 Electron에서 1920×1080 이미지를 사용했다. 앱 배율 80%·90%·120%·130%, 네 가지 창 크기, 전체 폭·절반 폭을 조합한 32개 조건을 수정 전후 동일하게 측정했다. 각 조건의 초기 20프레임을 제외한 연속 40프레임에서 최대값과 최소값의 차이를 비교했다.

| 조건 | 수정 전 이미지 폭 변화 | 수정 전 세로 위치 변화 | 수정 후 폭·위치 변화 |
| --- | --- | --- | --- |
| 1281×1037 창, 앱 120%, 전체 폭 | 13.0078px | 2.3438px | 0px |
| 921×775 창, 앱 130%, 전체 폭 | 10.9976px | 2.9086px | 0px |
| 921×775 창, 앱 80%, 절반 폭 | 19.0039px | 4.1602px | 0px |

수정 전 32개 중 9개 조건에서 1px 이상의 지속적 변화가 있었고, 수정 후에는 32개 모두 위치와 크기 변화가 0px였다. 새 회귀 검사 두 개도 수정 전 실패하고 수정 후 통과했다.

## 빌드 보완

독립 기준 체크아웃의 첫 빌드에서 이미지 내보내기 HTML 복사가 출력 디렉터리 생성과 경쟁하는 문제도 발견했다. 빌드 스크립트가 병렬 빌드·복사 전에 `dist-electron` 디렉터리 생성을 기다리도록 보완했다. 기준 체크아웃의 소스는 수정하지 않고, 첫 빌드가 생성한 디렉터리에서 메인 빌드를 완료했다.

## 전체 회귀 검사

`npm run test:preview-contract`를 실행해 73개 단위 검사 파일의 482개 테스트, 빌드 도구 검사 11개, 타입 검사·제품 빌드, 실제 Electron 검사 143개를 모두 통과했다. Svelte 오류·경고는 0개였고 GUI 재시도는 없다. 여기에는 사진 편집 10개 검사와 기존 Markdown·Git·PDF·이미지·브라우저·노트북·터미널·배율·포커스·한글 조합 검사가 포함된다.
