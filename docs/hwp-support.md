# HWP / HWPX 지원

Setdown은 로컬 `.hwp`, `.hwpx` 파일을 전용 탭에서 열고 편집·저장한다.
파일 열기, 탐색기, 파일 주소, 실행 인자에서 같은 경로를 사용한다.
문서 파서와 조판·편집 엔진은 직접 구현하지 않는다. `214c26a`가 추가한
HOP의 배포 WASM과 RHWP Studio를 사용한다.

## 사용

- 탐색기 상단의 `New HWP File` 버튼이나 폴더 우클릭 메뉴에서 이름을 입력하면
  선택한 폴더에 빈 `.hwp` 문서를 만들고 편집기로 연다. 확장자는 자동으로 붙으며,
  같은 이름의 기존 파일은 덮어쓰지 않는다.
- 글자·문단 서식, 표, 그림, 찾기, Undo/Redo는 RHWP Studio 도구 모음에서 제공한다.
- `Ctrl/Cmd+S`는 원래 경로에 저장하고 `Ctrl/Cmd+Shift+S`는 다른 이름으로 저장한다.
  새 경로의 `.hwp` / `.hwpx` 확장자가 내보낼 형식을 결정한다.
- `Esc`와 더블클릭은 HWP 편집기가 처리한다. Markdown 소스 화면으로 전환하지 않는다.
- 앱 확대 단축키는 공통 앱 확대를, 주소 표시줄의 HWP 배율과 편집기의
  배율·폭/쪽 맞춤은 문서 확대를 바꾼다.
  마지막 쪽과 문서 배율을 파일별로 기억한다.
- 일반 `New File`에서 `.hwpx` 이름을 입력해도 유효한 빈 문서를 만든다.
  빌드 시 고정된 엔진으로 빈 HWP 템플릿을 HWPX로 변환하며, 손실 보고서와
  다시 읽은 본문이 비어 있는지 확인한다. FIFO 등 일반 파일이 아닌 입력은
  writer를 기다리지 않고 거절한다.
- 탭 전환, 그룹 이동, 창 분리·이동은 같은 편집기를 유지한다. 저장한 뒤에도
  Undo 기록이 남는다. 닫기·창 종료는 공통 저장 확인을 사용한다.

## 저장 보장

본문은 Monaco 문자열 모델이나 `savedText`로 직렬화하지 않는다.
`DocumentContentOwner`가 문서의 수정 여부와 저장 요청을 담당하고,
메인 프로세스가 경로, 파일 바이트, 디스크 버전과 SHA-256을 소유한다.
RHWP의 `exportHwpWithReport` / `exportHwpxWithReport` 결과에서 바이트와
손실 보고서를 함께 받는다. 내보내기 오류 또는 알려진 손실이 있으면 원본을
덮어쓰지 않는다. 손실이 있는 사본은 새 경로와 명시적인 손실 확인이 필요하다.
손실 보고서가 비어 있어도 한컴 한글과의 완전한 호환성을 뜻하지는 않는다.

저장은 임시 바이너리 파일을 쓴 뒤 대상의 버전·해시와 소유자를 다시 확인하고
rename한다. 충돌·취소는 편집 내용을 유지한다. 저장 완료는 실제로 내보낸
revision만 인정하므로 저장 중 발생한 추가 편집은 수정 상태로 남는다.
이 방식은 파일시스템의 원자적 compare-and-swap을 제공하지 않으며,
마지막 확인과 rename 사이에 다른 프로그램이 쓰는 극히 짧은 경쟁 구간은 남는다.
한글 IME 조합 중에는 저장을 거절하고 입력 완료 후 다시 저장하도록 안내한다.

## 실행·빌드 경계

- HOP: `80888af2b8c8a18aea16f824d2d92309a290b1ad`.
- RHWP: `1a76570e833917d15817415a53c09ad61ab3203f` / 0.8.7.
- `scripts/build-hwp.mjs`는 필요한 두 하위 모듈만 초기화하고 HOP의
  `PROVENANCE.json`에 있는 여섯 배포 아티팩트의 크기와 해시를 검증한다.
  Rust, wasm-pack, HOP의 중첩 `third_party/rhwp` 체크아웃은 필요하지 않다.
- `hwp-runtime/`은 고정된 upstream Studio의 호스트 조립 코드다.
  esbuild가 vendor 소스를 함께 번들한다. 데스크톱 TypeScript 검사 범위 밖의
  upstream에 대해서는 별도 의미 분석을 수행하지 않으며 실제 실행 테스트로
  호스트 API 호환성을 검사한다.
- 문서마다 sandbox/context isolation을 켠 `WebContentsView`와 메모리 세션을
  만든다. `setdown-hwp://app/`는 배포 에셋 디렉터리만 읽는다. 원격 네트워크,
  팝업, 다운로드를 차단하며 런타임에 전체 `window.marktex` API를 주지 않는다.
  클립보드는 보이는 로컬 편집기에만 허용한다.
- Canvas2D와 로컬 글꼴을 사용한다. HOP의 재배포 글꼴 중 OFL/GUST 글꼴을
  동봉하며 별도 조건의 Cafe24/Happiness 파일은 배포하지 않고 Noto로 대체한다.
  저작권 고지와 라이선스는 `dist-electron/hwp/fonts/FONT-NOTICES.txt`에 포함한다.
  문서 글꼴은 Setdown의 Markdown D2Coding 스타일과 분리된다.
- HWP 런타임은 미디어 3개 LRU 캐시의 대상이 아니다. 닫거나 다시 불러올 때
  해제한다. 숨겨진 편집기가 포커스를 빼앗지 않도록 native view를 분리한다.
  셸 대화상자·메뉴를 표시할 때도 뷰를 숨기고 같은 인스턴스를 복원한다.

## 현재 범위와 제한

128 MiB 이하 입력을 지원한다. 암호·DRM 문서는 지원하지 않으며 원본을
변경하지 않고 오류를 표시한다. HWP 3는 엔진이 읽을 수 있는 경우 열 수 있지만
원본 덮어쓰기는 금지하고 HWP 5/HWPX 사본으로만 저장한다.

HWP에는 자동 저장, 충돌 병합, 편집기 크래시 복구, 검색 가능한 PDF 내보내기,
프로젝트 전체 본문 검색과 텍스트 Git diff를 아직 제공하지 않는다.
Undo로 저장 시점과 같은 내용이 되어도 수정 표시는 다음 저장까지 남을 수 있다.
여러 HWP 탭을 열면 각 엔진의 메모리 사용량이 증가한다.
한컴 전용 글꼴은 포함하지 않으므로 대체 글꼴로 줄바꿈·쪽 배치가 달라질 수 있다.

## 검증

`media/hwp-editor.spec.ts`는 엔진에 내장된 실제 한글 빈 문서 템플릿에서
본문과 표가 있는 HWP/HWPX를 만들고 실제 Electron/Chromium에서 열어
IME 조합, 저장·재열기, 클립보드 복사, 탭 왕복, 저장 후 Undo,
외부 변경 알림의 네이티브 화면 경계와 충돌, Save As 취소·성공,
창 이동 후 Redo, 닫기 취소, 주소 전환 후 올바른 파일 저장을 검사한다.
손실 보고서를 테스트에서 주입하여 원본 덮어쓰기 차단도 검사한다.
이는 실제 비지원 요소의 손실 검출 정확도를 검증하는 테스트와는 구별한다.
엔진의 `createEmpty()`는 구역·단 정의가 없는 테스트용 구조이므로 이 호환성
검증의 초기 문서로 사용하지 않는다. OS IME 후보 창이나 전체 한컴 문서 집합의
호환성을 증명하는 테스트는 아니다.

바이너리 읽기/쓰기, 텍스트 저장 배제, revision 확인은 단위 테스트로 검사한다.
이 테스트들과 기존 미리보기 계약을 격리 Xvfb에서 실행한다.
