코드를 포함시켜야 하는 경우...

1. 음. 간결하게 잘 적었군. 그런데 이 보고서의 문제는 
내가 이 보고서를 읽으면서 동시에 해당 코드를 계속 확인해야 한다는 점에 있다. 
왜냐면 코드의 기능이 이렇다~ 이렇게만 설명하고, 실제 코드를 첨부하지 않으니까. 
과거에는 그냥 코드를 지우거나, 아니면 커밋의 변화량이 크지 않았기 때문에 그냥 넘어갔는데. 
이 부분은 코드를 이해할 필요가 있다고 생각하지만, 
보고서의 지금 형식은 가독성이 매우 떨어진다고 생각한다

따라서, 코드와 리포트를 번갈아가며 읽지 않아도 되도록 보고서의 
지금 톤을 유지하면서도 적절하게 코드를 첨부해라.

2. 좋긴 좋은데. 코드를 그런 식으로 하니까 뭐가 중요한지 모르겟음

이건 어떠니
중요한 코드는 지금처럼 바깥에 노출시키고
안중요한 코드는 접었다 펼쳤다 할 수 있게

3. 펼쳐 보기에서는 코드 내용 뿐만 아니라 디렉토리 트리도 그려줘

4. 좋다. 매우 좋아.
마지막으로

(i) 니가 쓴 글이 내가 밑에 첨부한 이코노미스트 스타일이라는 본질을 잘 지키는지
(ii) 단순히 기계적으로 설명하지 마.
예를 들면, 글이 있으면, 사람들은 순서대로 읽잖니. 그러면 뒤에 정보가 적혀 있다고
 해서 사람들한테 "아니 50라인 뒤에 정보가 있으니까 그거 읽으면 알겠지? 그러니까 난 
 그냥 그걸 50라인 앞에서 적는다!" 이런 AI스러운 마인드를 버려.

5. 보고서를 쓴다는 행위의 본질을 생각해라
코드베이스를 읽는 것. 이것은 AI에게는 쉽지. AI는 그냥 글을 통째로 한큐에 읽어버리니까
인간에게 그것은 중노동이다. 중요하지 않은 코드라면 더더욱.
인간은 유한하다. 만약 AI가 코드베이스를 꿰뚫는 깊이있는 통찰을 해낼 수 있다면,
그래서 인간이 가장 중요한 부분의 코드를 곧바로 읽는 경로로 직행할 수만 있다면
인간의 생산성은 올라갈 것이고, 더 중요한 부분에 관심을 기울일 수 있을 것이고
읽는 양이 줄면서 동시에 코드베이스에 대한 직관을 가지는 놀라운 일이 일어난다.
