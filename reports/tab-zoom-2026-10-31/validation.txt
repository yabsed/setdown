Tab-owned zoom and persistent document initialization — 2026-10-31

Root causes
-----------
1. Code editors used a global code font factor, so unrelated tabs/windows changed together.
2. Website, Reader, PDF/image and ordinary text had different zoom owners.
3. Explorer preview replacement allocated a new tab ID, resetting tab-owned zoom.

Behavior
--------
One percentage belongs to each live tab. Resource changes and Back/Forward retain
that percentage. Explorer preview replacement retains the same tab ID. Separate
tabs remain independent, including separate windows showing the same file.
PDF and image percentages use original size. Fit controls calculate that same
percentage rather than adding a separate multiplier.

Document history only seeds a newly allocated file tab. Without history it starts
at 100%. History records zoom changes, both outgoing and incoming files on a
resource change, and tab/window close, including an unchanged older tab closed
after another tab changed zoom. The main process orders these events; renderer
scroll/focus notifications cannot overwrite history. Opening a new tab never
resets existing tabs. Values persist atomically in zoom-settings.json across
restart, without time-based or recent-file eviction. A new file surface waits for
initial zoom before mounting. Transfers retain their tab ID and percentage.

Native Chromium effective zoom still clamps app × tab to 25–500%; stored content
zoom supports 10–1000% so original-size media fits can be retained across surfaces.
This platform limit does not change the tab's recorded percentage.
